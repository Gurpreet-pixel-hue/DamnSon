## 1. Deterministic repository reads (`lib/data/graphRepository.ts`)
- `fs.readdirSync` order is OS-dependent: sorted on macOS, not on Linux or on Vercel. That makes both `listTasks()` order and "which duplicate wins" nondeterministic, which breaks the determinism rule.
- Sort `fileNames` with `localeCompare` before reading. Seed files are read before demo files, as now.
- `listTasks()` returns summaries sorted by `title`, then `taskId`.
- Test: create files `b.json` and `a.json` holding the same `taskId` in a temp dir, in that order. `a.json` must win regardless of creation order, and `console.error` must name `b.json`.

## 2. Validate persisted progress instead of casting (`lib/store/useTaskStore.ts`)
- The `migrate` casts (`as Record<…>`) break the "parse unknown data with zod, no casts" rule. `migrate` only runs on a version change, and zustand's default `merge` accepts whatever is in localStorage. A tampered or corrupted value (e.g. `completedByTask: "x"`) would crash the UI later.
- Add `persistedProgressSchema` in the same file:
  ```ts
  const persistedProgressSchema = z.object({
    completedByTask: z.record(z.string(), z.array(z.string())).catch({}),
    answersByTask: z.record(z.string(), z.record(z.string(), z.boolean())).catch({}),
  });
  ```
- Use it in both `migrate` and a custom `merge: (persisted, current) => ({ ...current, ...persistedProgressSchema.parse(persisted ?? {}) })`. No casts.
- Tests:
  - Corrupted storage `{ completedByTask: "x", answersByTask: { t: { q: "yes" } } }` rehydrates to `{}` for the broken fields and doesn't throw.
  - Valid storage round-trips.
